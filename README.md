# Telegram-планировщик

Telegram-бот для планирования событий, напоминаний и повторяющихся задач. Данные хранятся локально в SQLite, а напоминания отправляются планировщиком задач во время работы бота.

> Проект находится в стадии разработки. В репозитории пока нет файла зависимостей, автоматических тестов и конфигурации для развёртывания.

## Возможности

- добавление событий с названием, датой и временем;
- просмотр списка событий;
- удаление событий;
- редактирование названия, даты и времени;
- напоминания за 5, 10, 15, 30, 60, 120 минут или за пользовательское количество минут;
- повтор событий каждый день или каждую неделю;
- автоматическое удаление прошедших неповторяющихся событий;
- расчёт среднего балла, в том числе по взвешенным оценкам.

## Стек

- Python;
- `python-telegram-bot` — работа с Telegram Bot API;
- APScheduler — планирование напоминаний;
- SQLite через стандартный модуль `sqlite3`.

Версии зависимостей в репозитории не зафиксированы: файлов `requirements.txt`, `pyproject.toml` и других манифестов пакетов нет.

## Структура

```text
.
├── bot.py       # основной код Telegram-бота и точка запуска
├── database.db  # локальная база событий SQLite
└── 123.py       # одноразовая миграция старой схемы базы данных
```

Файл `database.db` является рабочими данными приложения и входит в репозиторий. Перед экспериментами с кодом или схемой сделайте его резервную копию.

## Требования

- Python 3;
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather);
- установленные пакеты `python-telegram-bot` и `apscheduler`.

Поскольку манифеста зависимостей пока нет, пакеты можно установить вручную в отдельное виртуальное окружение:

```bash
python -m venv .venv
```

Windows:

```cmd
.venv\Scripts\activate
python -m pip install python-telegram-bot apscheduler
```

Linux/macOS:

```bash
source .venv/bin/activate
python -m pip install python-telegram-bot apscheduler
```

## Настройка и запуск

1. Настройте токен Telegram-бота безопасным способом.
2. Перейдите в каталог репозитория, чтобы относительный путь к базе данных указывал на `database.db` в этом каталоге:

   ```bash
   cd tg_bot
   ```

3. Запустите бота:

   ```bash
   python bot.py
   ```

При успешном старте приложение выводит сообщение `Telegram бот запущен...` и начинает polling Telegram.

> В текущей версии токен читается непосредственно из исходного файла `bot.py`. Это небезопасно для публикации и развёртывания. Перед использованием проекта необходимо отозвать уже раскрытый токен, выпустить новый и вынести секрет в переменную окружения или другой некоммитимый конфигурационный источник. Изменение способа хранения секрета в этот README-коммит не входит.

## Использование

После команды `/start` бот показывает основное меню.

### Добавление события

Событие вводится одной строкой. Поддерживаются даты в формате `дд.мм`, `дд.мм.гг` или `дд.мм.гггг` и время в формате `чч:мм`:

```text
Тренировка 13:00 11.11
Репетитор 18:00 12.12.26
Поездка 13:00 11.11.2027
```

Для нового события автоматически устанавливается продолжительность 60 минут.

### Оценки

Оценки вводятся через пробел. Поддерживаются обычные оценки, повторение оценки заданное число раз и дробные оценки:

```text
5 4 3
5x3 4
3/4 5
4/5x3
```

### Напоминания и повторения

Для события можно включить напоминание или отключить его. Напоминание является одноразовой задачей и восстанавливается из базы данных после перезапуска, если событие ещё актуально.

Повторение доступно в двух режимах:

- каждый день;
- каждую неделю.

Состояние диалога пользователя хранится в памяти процесса и теряется после перезапуска. События и настройки напоминаний хранятся в SQLite.

## База данных и миграция

Приложение использует относительный путь `database.db`, поэтому запуск из другого каталога может создать или открыть другую базу данных.

При запуске `bot.py` приложение проверяет и при необходимости добавляет используемые столбцы схемы. Файл `123.py` — историческая одноразовая миграция для добавления столбца `remind`; он не нужен для обычного запуска и не предназначен для повторного выполнения без проверки текущей схемы.

## Проверки

